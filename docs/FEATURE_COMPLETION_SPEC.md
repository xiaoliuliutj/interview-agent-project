# 面试 Agent 功能完善说明

本文定义本轮优化的可交付边界，以及上下层的职责和交互。前端复用原项目仍适用于三条业务线的页面，并只调用当前业务接口；语音面试不在本轮实现。

## 1. 总体职责

| 层 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| Java 上层 | 候选人、简历、JD、面试会话等业务实体；权限归属校验；事务、乐观锁、幂等、异步任务、RabbitMQ、Redis 缓存和简单限流；文件存储与 PDF 下载；前端业务 API | Prompt、Skill 内容、模型推理、RAG 证据直接展示、Agent 状态机决策 |
| Python 下层 | 独立的面试 Agent；Skill 自动选择和调用；计划、出题、追问、回答评估和总结；会话历史、3~5 轮短期记忆、用户长期记忆；Agent 内部 RAG 检索与证据编排；简历结构化评估 | 上层业务实体和鉴权；前端协议；业务数据库事务编排 |

下层只通过稳定 JSON 合同识别 `userId`、`sessionId`、`runId` 和初始化快照。除初始化时指定的 `difficulty` 外，上层不传递对话上下文；历史由下层按用户和会话恢复。

## 2. 文字面试 Agent

一次会话包含 OPENING、PROJECT、FUNDAMENTAL、SCENARIO、CODING、SUMMARY 六个阶段。创建会话时上层传递 `difficulty`（EASY/MEDIUM/HARD），下层在第一轮生成计划并固化到会话，后续轮次不得改变难度。

下层在每次规划和决策时从配置目录加载 Skill。Skill 由 Agent 根据目标职位、JD 和历史薄弱点选择；当前文本面试只通过受控的内部 `RagSearchTool` 读取 RAG，评分节点不具备该工具。`allowedTools` 作为 Skill 能力声明保留，用于后续 MCP/工具编排扩展；Java 只读取公开目录，不保存 Skill 正文。

候选人提交回答后，下层先完成本轮评估，再决定追问、换题或换阶段；只有方向确定后才读取 RAG 缓存或检索并生成具体题目。每轮内部记录包含分数、回答摘要、优势和薄弱点，但 Java 只持久化问题、回答和会话状态。SUMMARY 阶段先对所有轮次综合评分，再反馈总分、表现总结、优势、弱势和后续建议。

## 3. 双层记忆和会话恢复

- 会话记忆：保存完整历史、当前阶段、计划、当前问题、状态版本和幂等快照；恢复会话时从持久化历史读取。
- 短期记忆：每次决策取最近 3~5 个已完成回答（数量由配置限定），与当前问题一起交给 Agent。
- 长期记忆：按 `userId` 跨会话保存历史摘要、简历快照、偏好、薄弱点、notes、已提问问题目录和面试总结。新的会话可读取同一用户的长期记忆，避免重复考察并针对薄弱点出题。
- 正常完成或显式结束会话时才生成会话摘要并写入长期记忆；`PAUSED` 表示可恢复中断，不会提前归档。模型、RAG 或网络异常不伪造完成状态，保留原会话供同一 `runId` 或后续恢复重试，不能删除已有长期记忆。

## 4. RAG

RAG 资料由上层上传/管理，下层负责切片、向量化和检索。只有路由已确定下一题方向且会话缓存未命中时，出题 Agent 才调用 RAG Tool；检索证据仅作为内部上下文，接口不直接返回命中的原文片段。系统不提供独立 RAG 问答接口。

同一会话的相同查询先查下层的短期检索缓存（生产部署可映射到 Redis，当前下层也保留内存回退），未命中才执行向量检索。缓存键至少包含知识库范围、用途和归一化查询，避免跨用户泄露。

## 5. 简历分析

Java 保存原始文件、SHA-256 哈希、原始文件名、大小、Content-Type 和可下载的存储键；相同用户上传相同哈希时复用已有简历。解析后的文本交给 Python Resume Agent，结果遵循原项目结构：问题、优先级、建议，并附结构化评分、优势和摘要。Java 通过 RabbitMQ 异步持久化分析状态；下层把简历快照及分析结论写入该用户长期记忆。简历和面试导出接口均返回真实 `application/pdf` 报告，原始文件下载接口返回原文件。

## 6. Java 工程化

- 可靠性：下层调用设置连接/读取超时、有限重试、幂等 `runId`、失败状态和补偿任务。
- 异步：简历分析和 RAG 索引通过 RabbitMQ durable queue；文本面试初始化和逐轮回答保持同步请求/响应，以便前端立即获得下一条消息。消息只携带资源 ID，消费者重新加载数据库数据，采用自动确认、有限重试和死信队列。Redis 只用于短期缓存和限流，不使用 RedisStream。
- 一致性：业务会话使用 JPA 乐观锁；消息采用 outbox/任务表记录状态，消费者以业务键幂等执行。
- 限流：仅实现按 IP/用户的简单固定窗口限流，返回 429；鉴权由后续版本负责。

## 7. 版本边界

本轮不实现语音、ASR/TTS、复杂多智能体编排、完整鉴权和生产级分布式限流。RabbitMQ、Redis、PostgreSQL/pgvector 均提供 Docker Compose 配置；模型密钥只来自未提交的环境文件。知识库资料已按用户归属校验，旧数据库中没有归属的历史记录需管理员迁移后才能被普通用户访问。

## 8. 验收重点

Python 测试验证难度固化、Skill 自动选择、每轮评估和摘要、双层记忆、RAG 不泄露 chunk 及检索缓存、简历评估结构；Java 通过静态编译级检查和契约测试验证 RabbitMQ 配置、幂等任务、原文件/PDF 响应和限流行为。
