# 面试工作流设计

## 1. 总体结构

面试分为“面试规划”和“正式面试”两个大阶段：

```text
候选人资料
  → 生成 InterviewPlan
  → 开始
  → 项目深挖
  → 基础知识
  → 场景题
  → 算法手撕
  → 总结
```

规划阶段根据候选人的工作年限、实习经历、项目丰富度、目标岗位和技能覆盖生成结构化计划。正式面试严格按六个阶段推进，但中间四个阶段的题量、难度、主题和追问上限由计划决定。

## 2. 规划原则

- 有较丰富实习或工作经验：减少纯基础题，增加项目深挖、技术取舍和场景设计。
- 缺少实习或工作经验：增加基础知识与算法考察，但仍保留个人项目追问。
- 没有可深挖项目：项目阶段允许配置为零轮或替换为课程设计、个人练习经历。
- 即使经验丰富，也保留少量基础题用于校准，不完全跳过基础能力验证。
- 简历信息不足时采用默认计划，不让模型臆测候选人经历。

规划只确定阶段配额、知识范围和难度，不提前生成全部问题。具体问题在进入相应阶段后，严格按“评估回答 → 路由追问/换题/换阶段 → 确定题目方向 → 读取证据缓存或执行 RAG → 生成具体题目”的顺序动态产生。

## 3. 六阶段定义

| 阶段 | 职责 | 轮次规则 |
|---|---|---|
| `OPENING` | 开场、自我介绍和方向确认 | 固定一轮 |
| `PROJECT` | 项目职责、方案选择、难点和改进 | 由计划设置主问题上限和单题追问上限 |
| `FUNDAMENTAL` | 语言、框架、数据库、中间件和计算机基础 | 由计划设置主问题上限和难度 |
| `SCENARIO` | 一致性、并发、幂等、失败处理和系统设计 | 由计划设置主问题上限和难度 |
| `CODING` | 算法思路、编码和复杂度分析 | 由计划设置题量上限，首期通常一题 |
| `SUMMARY` | 生成评价、优缺点和学习建议 | 固定一次输出，不要求候选人再次回答 |

“一轮”默认表示一次 Agent 提问和一次候选人回答。`SUMMARY` 是一次下层输出，不计入候选人问答轮次。

## 4. 阶段配置

中间阶段不直接配置固定总轮数，而是区分：

- `maxPrimaryQuestions`：主问题上限。
- `maxFollowUpsPerQuestion`：每个主问题的追问上限。
- `difficulty`：初始难度。
- `topics`：目标知识范围。
- `timeBudgetMinutes`：可选的阶段时间预算。

上限不是必须用满的数量。Agent 在覆盖目标已经满足、候选人明显不会或时间不足时可以提前进入下一阶段。

## 5. 回答后的行为决策

每次回答后，Agent 只能选择以下行为：

- `FOLLOW_UP`：围绕当前问题继续追问。
- `NEXT_QUESTION`：当前阶段切换主问题。
- `NEXT_STAGE`：完成当前阶段并进入下一阶段。
- `END_INTERVIEW`：提前结束面试并进入总结。

决策依据包括回答相关性、正确性、完整度、追问次数、知识覆盖、剩余题量和时间预算。单个主问题首期最多追问两次，防止对一个知识点无限深入。

## 6. 上下层职责

- 上层负责用户、候选人资料、面试业务会话、开始/暂停/结束和最终结果持久化。
- 下层负责生成 InterviewPlan、维护 Agent 会话上下文、阶段推进、问题选择、追问决策、记忆、RAG 和总结生成。
- 候选人资料只在初始化或规划阶段提供一次；正式问答请求不重复传递上下文。
- 下层了解面试策略，但不依赖上层 Java 实体、表结构或具体业务实现。

## 7. 首期范围

- 采用单 Agent，不实现多 Agent 编排。
- 算法阶段先支持文本代码与思路分析，不执行候选人代码。
- InterviewPlan 必须使用结构化模型并持久化，避免每轮重新规划。
- 阶段流转由状态机约束，阶段内部由受约束 ReAct Agent 决策。

## 8. 知识库边界

首期 RAG 的目标是为已经确定方向的题目生成提供可靠的题目素材和参考事实，不参与回答评分、追问方向、阶段路由或结束决策。普通用户可以维护自己的知识库，面试时与系统知识库联合检索。

- 知识库由项目维护者预置并离线导入，普通候选人只使用检索能力，不具备上传、删除或选择任意知识库的权限。
- 题库内容至少按岗位方向、技术主题、难度、面试阶段、问题类型、追问关系和参考答案组织。
- Agent 先由 Prompt/Skill 完成回答评分，再由独立路由节点决定追问、换题、换阶段或结束；只有需要生成具体题目时，才使用阶段和路由返回的题目方向读取缓存，未命中才检索系统知识库与用户知识库。
- 候选人简历属于一次会话的输入资料，不等同于知识库文档；后续如支持简历解析，应走独立的简历处理链路。
- 当前前端已有的知识库上传、管理页面不作为候选人端首期功能。需要保留时，应改造为项目维护者的离线导入或管理员能力。
