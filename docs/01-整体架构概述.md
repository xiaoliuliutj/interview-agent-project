# InterviewGuide 整体架构概述

本文以当前代码为准。旧设计说明已归档在 docs/archive，不作为当前实现依据。

## 1. 系统职责边界

InterviewGuide 的唯一外部请求链路是：浏览器 → React/Nginx → Java Backend → Python Agent。Java 负责身份、业务数据、事务、异步任务以及对 Python 的内部调用；Python 负责 Agent、Skill、RAG、记忆、网页证据工具和模型调用。

实际部署中，python-agent 只有 Docker expose 8000，没有宿主机 ports；frontend/nginx.conf 和 frontend/vite.config.ts 只将 /api 指向 Java 8080。浏览器不能访问 Python /v1/**。

<span style="color:blue">新知识：服务边界</span>

服务边界是“每个服务只负责自己的职责”。前端只提交 interviewDirection、JD、简历和岗位等业务参数；Java 不实现 Agent、Skill、RAG、Memory 或 Prompt；Python 在内部根据方向、JD、简历和用户画像选择 Skill 并执行 Agent。

## 2. Java 目录

Java 根包只有 com.interviewguide，位于 java-backend/src/main/java/com/interviewguide：

common：跨模块异常、身份和响应模型；infrastructure：RabbitMQ、限流、可靠调用和请求链路；interview：面试业务；resume：简历业务；knowledgebase：知识库业务；web：网页预览与确认导入；pythonagent：Java 调用 Python 的内部客户端。

每个业务目录下分别有 controller、service、domain、dto、mapper。Controller 接收 HTTP，Service 编排业务，Mapper/Repository 访问数据库或远程资源。pythonagent 没有 Controller，只有 DTO、配置、异常和 mapper/PythonAgentClient.java、mapper/HttpPythonAgentClient.java。

## 3. 主要流程

前端在 frontend/src/pages/InterviewHubPage.tsx 或 components/UnifiedInterviewModal.tsx 收集方向、难度、简历、JD 和岗位，调用 Java POST /api/interviews。InterviewService.start 验证简历归属和版本，创建本地会话，然后调用 PythonAgentClient.initialize。Python 返回首题和状态版本，Java 激活会话。

提交回答时，Java 将 runId 和 stateVersion 传给 Python。Python 按“评估回答 → 路由追问或换题 → 必要时检索证据 → 生成下一题”执行，Java 保存问题、回答和评分。

简历上传由 Java 保存文件和版本，再通过 RabbitMQ 异步调用 Python 分析。知识库上传由 Java 先落库，再由 Python 切分、Embedding 和检索。网页先预览，用户确认后才导入知识库。

## 4. Python 目录

python-agent/app/agents 负责规划 Agent、面试 Agent、简历评估和 LLM；app/rag 负责自研切分、Embedding、检索和仓储；app/memory 负责短期会话和长期画像；app/tools 负责 Skill、RAG、网页和 MCP 工具；app/common 负责配置、契约、异常和 Prompt；app/infrastructure 负责幂等、可靠性和持久化；app/api 只提供 Java 内部调用入口；resources 保存 Prompt、Skill、RAG 和 Agent 配置。

### 规划 Agent

InterviewPlanner.create_plan 位于 python-agent/app/agents/interview/agent.py。它从真实 Skill 注册表取得白名单，由模型在白名单内选择 Skill，生成 OPENING、PROJECT、FUNDAMENTAL、SCENARIO、CODING、SUMMARY 六阶段计划，检查项目/实习、技术栈、知识与实操三类覆盖，不足时最多修订两次，每次最多 45 秒。

程序强制总题数最多 20；中间阶段最多 4 道主问题；单主问题最多 2 次追问；CODING 最多 2 道；OPENING 和 SUMMARY 各 1 道。

### 面试 Agent

面试 Agent 每轮固定执行评估、路由、证据检索、出题和持久化。评估节点不路由，路由节点不出题，出题节点才使用 RAG/Web 证据。每个节点只输出 Schema 校验后的 JSON，不输出思维链；循环次数和超时由代码控制。

<span style="color:blue">新知识：ReAct</span>

ReAct 是“观察输入 → 选择受限动作 → 获取结果 → 下一步”的循环。本项目使用受控 ReAct，动作、题量和超时都由程序限制，防止无限思考。

## 5. Skill、RAG、Memory

Skill 完全属于 Python。tools/skills/loader.py 从 resources/skills 读取 skill.json 和 SKILL.md。前端和 Java 不选择或暴露 Skill ID；interviewDirection 只是 Python 的内部筛选上下文。

<span style="color:blue">新知识：RAG</span>

RAG 是“先检索相关证据，再让模型生成”。rag/parser.py 自行切分文档，rag/embedding.py 获取向量，rag/service.py 编排检索，rag/repository.py 持久化向量。它不是把所有文档盲目塞进 Prompt。

Memory 保存最近轮次、摘要、已问问题、当前题证据，以及简历分析得到的技术栈、偏好和薄弱项。实现位于 app/memory，长期数据写入 agent_long_term_memories。
