# 业务线实现规范

## 1. 目标与边界

本项目只有一个面向前端的面试业务入口：`/api/interviews`。不保留旧的
`/api/interview/sessions` 兼容接口、DTO 或适配层。前端仅保留文本面试页面，
不保留没有 Java 控制器支撑的语音面试路由、WebSocket 或 REST 调用。

上层（Java）负责身份校验、文件处理、业务资源、任务状态、对前端的响应和
跨服务调用；下层（Python）负责简历画像、会话记忆、Agent 规划/决策、RAG
检索和模型调用。下层响应中的内部评分、记忆和检索证据不直接暴露给前端。

所有运行期需要的参数都由调用方显式传入。不得以固定题量、固定时长、固定
岗位、占位用户或占位会话替代调用参数。

身份解析出的 `userId` 是候选人资源的唯一归属；创建候选人记录时直接使用该真实
身份值作为显示标识，不生成固定的占位姓名或占位用户。

## 2. 业务线一：简历上传、解析、分析与画像

同一用户重复上传相同文件时复用已持久化的文件与解析文本，但仍以本次 `targetRole`
取消旧分析并创建新任务；不会静默返回与本次岗位不一致的旧分析结果。

旧版本仅用于下载、浏览与审计。重新分析和创建新文本面试都必须校验
`candidates.current_resume_id`，只允许当前版本进入 Agent 主链路。

### 2.1 状态流

`UPLOADED -> PARSED -> PENDING -> PROCESSING -> COMPLETED | FAILED | CANCELLED`

1. 上层校验文件并保存原始文件，解析出文本后创建新的简历版本。
2. 每个用户有一个当前简历指针；新版本成为当前版本时，旧版本尚未完成的
   分析任务被标记为 `CANCELLED`。消费者执行前、激活下层画像后和模型返回后
   都检查当前指针；已取消或已过期任务不得写入结果。
3. 消费者先以真实的 `userId`、`resumeId`、`candidateId`、`targetRole` 和解析文本
   调用下层 `agent.resume.activate`，把该版本设为长期画像的唯一可写简历；再用同一组
   真实参数和 `runId` 调用简历评估。下层仅接受当前简历版本写入技术栈、技术深度和偏好，
   所以迟到的旧评估无法覆盖新版画像。
4. 分析超时、模型临时错误和网络错误按可重试策略重投；参数、解析、数据归属
   和模型结构化输出错误不重试。
5. 对同一当前简历发起重新分析时，新的分析任务会取消该简历仍处于 `PENDING` 或
   `PROCESSING` 的旧任务；同一简历版本同时只有一个可写分析任务。
6. 简历原文件可下载，解析文本和评估结果可浏览。历史版本可保留审计记录，
   但前端默认只展示当前版本。

## 3. 业务线二：文本面试

### 3.1 初始化

系统知识库配置和索引状态在上层创建会话记录前校验；校验失败时不创建
`INITIALIZING` 会话，避免留下无法恢复的半初始化资源。

前端显式提交 `resumeId`、`targetRole`、`difficulty`、`interviewDurationMinutes`、
`questionCount`、`skillId`（可为空）和自定义分类。Java 从认证身份取得 `userId`，创建上层会话
和稳定的 `sessionId`，再把同一组真实参数传给 Python。

Python 使用用户画像、当前简历、岗位信息、Skill 和显式 `questionCount` 生成六阶段面试计划。阶段
为：开场、项目深挖、基础知识、场景题、算法、总结。计划中的每个题目上限和
追问上限是唯一的执行约束；六个阶段的主问题上限之和必须严格等于 `questionCount`，
前端显示的题量从该计划汇总得到，不能单独伪造。

### 3.2 每轮回答

1. 前端为一次提交生成并稳定复用 `runId`；超时重试必须沿用该 ID。
2. Java 校验会话归属、当前版本和状态，再向 Python 转发 `userId`、`sessionId`、
   `runId`、候选人回答和上层会话版本。
3. Python 先读取短期会话记忆、长期用户画像，以及生成当前题时已经持久化的
   证据缓存，并由专门的评分节点使用 Interview Skill 和 `evaluation.md` 定义的评分标准评估
   回答；缓存仅用于事实核对，不能新增评分维度或改变评分标准，评分阶段不得发起知识库检索。评分完成后，独立路由节点只依据评分结果、
   会话计划和阶段配额决定追问、下一题、下一阶段或结束。
   当前问题、回答、评分和路由结果会先写入下层会话的短期记忆视图；因此后续出题可使用本轮回答，但长期用户记忆只在完整的下一会话状态成功持久化后更新。
4. 仅当已确定需要一条具体的新题时，Python 才根据已经确定的题目方向查询
   会话级 RAG 缓存；缓存未命中时才检索知识库，并将结果写入缓存。RAG 不得
   决定评分、是否追问、是否换阶段或题目方向。
5. Python 只向 Java 返回下一条面试消息、下层会话版本和状态。评分、画像、
   记忆摘要、RAG 证据为下层内部数据；Java 不将其映射到前端。
6. 前端为一次待提交回答生成并保留稳定 `runId`；网络失败后以相同 `runId` 和
   相同回答重试，修改回答才生成新的 `runId`。Java 校验同一 `runId` 不得关联
   不同会话或不同回答；Python 下层也持久化原始回答并执行同样的幂等校验，防止
   上层第一次保存失败后被不同回答抢占。Java 单独保存 Python 返回的 `agentStateVersion`；JPA 行版本
   只负责上层数据库并发，不冒充下层 Agent 版本。浏览器在当前会话内保存尚未确认的提交信息，刷新页面后仍可重放同一 `runId`。
   会话中断后，
   Java 读取未完成会话并调用下层恢复同一 `sessionId`；不得重新初始化 Agent。

## 4. 业务线三：系统与用户知识库联合 RAG

系统知识库由部署者离线导入，具有稳定 ID 和版本；用户知识库由用户上传并且
严格按 ownerId 隔离。仅在已完成“回答评分和下一步决策”且需要生成新题时，
才联合检索：

`systemKnowledgeBaseIds + currentUserKnowledgeBaseIds`

上层负责查出当前用户已完成索引的知识库 ID，并把两类 ID 显式传给下层。下层
只使用 `QUESTION_GENERATION` 用例检索，不允许用空 ID 隐式回退到未知默认知识
库。缓存存放在会话内；缓存键由阶段、题目方向和本次会话选定的系统/用户知识库
ID 集合组成。知识库范围变化时必须创建新的会话，不能复用旧会话缓存。
没有可用知识库或检索失败时，面试可降级为无证据的出题，但必须记录可观察的
降级原因；用户上传知识库的管理、上传、下载、删除和重新索引继续保留。

系统题库通过 `scripts/import-system-knowledge-base.sh` 走同一份“上传 → 异步向量
索引 → 状态轮询”真实链路导入。脚本仅在索引完成后输出可写入
`AGENT_SYSTEM_KNOWLEDGE_BASE_IDS` 的 ID；Java 在启动面试时再次校验这些 ID 均为
`COMPLETED`，不会把未完成索引的资料传给下层。

## 5. 异常与重试约定

简历分析任务记录 `retryCount`、`lastAttemptAt` 和最近错误。仅下层网络、超时或模型
服务故障属于可重试错误：任务在 Rabbit 重试上限内保持 `PROCESSING`，每次重新执行
都会递增尝试次数；达到上限才进入 `FAILED`。参数、文件解析、权限和结构化输出错误
直接失败，不进行无意义重试。新简历上传取消旧任务后，取消任务不得被重新执行或覆盖。

下层统一使用三位 `code`，成功与失败使用同一 JSON 字段集：

| 类别 | 含义 | 上层动作 |
| --- | --- | --- |
| `1xx` | 成功或部分结果 | 持久化业务状态并向前端返回业务结果 |
| `2xx` | 参数、文件格式、状态机不合法 | 不重试，返回可理解的前端错误 |
| `3xx` | 会话/版本/资源一致性错误 | 不自动盲重试；刷新资源或由用户重新操作 |
| `4xx` | 限流或队列容量问题 | 告知稍后重试，携带 `retryAfter`（如有） |
| `5xx` | 模型、工具、网络、向量库临时故障 | 按任务策略重试；超过次数标记失败 |

异步任务使用 `PENDING/PROCESSING/COMPLETED/FAILED/CANCELLED` 状态。取消不是
删除记录：消费者必须识别 `CANCELLED`，并确认不会把旧任务结果写入当前简历。
同步回答使用稳定 `runId` 幂等；同一会话同一时刻只允许一个运行中的回答命令。

## 6. 禁止项

- 不保留已废弃接口、旧 DTO、Facade 或“兼容适配层”。
- 不用 `"Candidate"`、固定 `40` 分钟、固定题量、默认岗位或随机替代 ID 填充
  本应由调用方传递的数据。
- 不以空方法、TODO、mock 返回值或只声明路由来代替功能实现。
- 前端不得直接相信 `X-User-Id` 以外的 body userId；生产替换为认证上下文后，
  仍以服务端身份为准。
