# InterviewGuide 技术细节

## 1. Java 接口与调用链

所有浏览器请求先进入 Java；Python 的 `/v1/**` 仅允许 Docker 内部的 Java 调用。核心面试链路为：`InterviewController` → `InterviewService` → `PythonAgentClient` → `HttpPythonAgentClient`。

面试模块接口包括：`POST /api/interviews` 创建会话并调用 Python 初始化；`POST /api/interviews/{id}/answers` 携带 `runId` 和 `stateVersion` 调用 Python 评估、路由、检索和出题；`GET /api/interviews`、`GET /api/interviews/{id}`、`GET /api/interviews/unfinished/{resumeId}` 查询会话；`POST /api/interviews/{id}/complete`、`POST /api/interviews/{id}/pause`、`DELETE /api/interviews/{id}` 管理会话；`GET /api/interviews/{id}/agent-status` 查询内部进度，`GET /api/interviews/{id}/export` 由 Java 使用已持久化内容生成 PDF。

简历模块位于 `resume/controller`：上传、列表、详情、导出、下载、重新分析和删除。上传先由 Java 保存文件、文本、版本和哈希，再通过 RabbitMQ 异步调用 Python。知识库模块位于 `knowledgebase/controller`：上传、列表、下载、分类、搜索、统计、重向量化和删除。网页模块位于 `web/controller`：先预览抓取结果，用户确认后才导入知识库。

## 2. Java 到 Python 的内部协议

`java-backend/src/main/java/com/interviewguide/pythonagent/` 只包含 HTTP 客户端与契约。`AgentInitializeRequest` 传递简历、JD、岗位、难度、方向和知识库范围；`AgentRespondRequest` 传递 `runId`、`stateVersion` 和回答；还有完成、简历评估、RAG 索引/删除与网页抓取契约。

`HttpPythonAgentClient` 在发送前校验 DTO，使用 `AgentCallExecutor` 对可重试网络和 5xx 错误做有限重试，并将下游错误转换为统一业务错误。它不实现 Agent、Skill、RAG、Memory 或 Prompt。

Python 内部接口在 `python-agent/app/api/application.py`：会话初始化、答题、完成、简历评估、RAG 索引/删除和受控网页抓取。它们并非浏览器 API：Compose 只在内部网络暴露 8000，Nginx/Vite 不代理 `/v1/**`。

## 3. Python Agent 与结构化输出

<span style="color:blue">新知识：结构化输出</span>

模型天然输出文本。`python-agent/app/infrastructure/reliability/structured_output.py` 强制模型仅返回 JSON，并用 Pydantic Schema 校验字段、类型、枚举和数值范围；格式错误时有限纠错重试，持续失败则抛出受控异常。Prompt 位于 `python-agent/resources/prompts/`。

规划 Agent 位于 `python-agent/app/agents/interview/agent.py`：从真实 `SkillRegistry` 白名单选择内部 Skill，生成 OPENING、PROJECT、FUNDAMENTAL、SCENARIO、CODING、SUMMARY 六阶段计划，检查项目实习、技术栈、知识实操三类覆盖；不足时最多修订两次，每次最多 45 秒。程序强制总题数最多 20，中间阶段最多 4 道主问题，单题最多 2 次追问，CODING 最多 2 题。

面试 Agent 每轮固定执行：评估回答 → 路由动作 → 必要时检索 RAG/Web 证据 → 生成问题 → 持久化。评估节点不路由，路由节点不出题，出题节点才使用证据工具。

规划、评估、路由和出题均使用统一的 45 秒节点超时包装；答题 HTTP 请求整体上限是 150 秒。RAG 最多 30 秒，网页证据最多 15 秒；RAG/Web 失败会记录日志并降级为无外部证据出题，而不会卡死会话。

Python 的工具分层为：

- `tools/skills/loader.py`：读取并校验 `resources/skills/*/skill.json` 与 `SKILL.md`，模型只能从运行时白名单选择内部 Skill。
- `rag/service.py` 中的 `RagSearchTool`：自研切块、向量检索和知识库范围过滤，用于确定主题后的出题证据。
- `tools/web_search.py` 中的 `WebEvidenceTool`：仅在本地 RAG 证据不足时检索受限技术文档域名。
- `tools/web_reader.py`：校验公开 URL、拦截私网/本地地址并限制抓取范围，防止 SSRF。

这些工具由 Agent 服务代码按受控流程调用，不把自由的网络或数据库权限交给模型。

## 4. 数据库

数据库定义见 `infrastructure/postgres/init/001-schema.sql`；兼容升级见 `002-feature-upgrade.sql` 与 `005-interview-direction-upgrade.sql`。

| 表 | 真实作用 |
|---|---|
| `candidates` | 保存候选人和当前简历归属。 |
| `resumes` | 保存简历文本、文件位置、版本和哈希。 |
| `resume_analyses` | 保存异步简历分析状态和结果。 |
| `job_descriptions` | 保存 JD 快照。 |
| `interview_sessions` | 保存 Java 会话、权限、恢复状态和 Agent 状态版本。 |
| `interview_turns` | 保存问答，`run_id` 唯一保证幂等。 |
| `knowledge_bases` | 保存知识库内容和向量化状态。 |
| `agent_interview_sessions` | 保存 Python 完整 Agent 会话 JSON、计划和快照。 |
| `agent_long_term_memories` | 保存 Python 用户级长期画像。 |
| `agent_rag_chunks` | 保存 RAG 切块、元数据和 pgvector 向量。 |

`interview_direction` 是业务方向，绝不是 Python 内部 Skill ID；升级脚本只在旧 `skill_id` 列实际存在时才做兼容迁移。

## 5. 工程化

<span style="color:blue">新知识：幂等</span>：同一操作重试多次，最终效果仍像只执行一次。答题强制 `runId`；Python 保存运行快照，Java 的 `interview_turns.run_id` 有唯一索引。网络重试复用同一 `runId`，不会重复推进题目。

<span style="color:blue">新知识：乐观锁</span>：`stateVersion` 是会话版本。Java 将版本传给 Python；Python 只接受匹配版本的写入并递增，过期请求不能覆盖更新状态。

RabbitMQ 用于简历分析和知识库索引等耗时任务。配置在 `infrastructure/messaging/RabbitTaskConfiguration.java`；投递在 `ResumeAnalysisWorker`、`KnowledgeBaseIndexWorker`；消费分发在 `RabbitAgentWorkConsumer`。

<span style="color:blue">新知识：Redis</span>：Redis 是内存键值数据库，常用于跨实例缓存、分布式限流和短期状态。项目已部署 Redis，但当前 `SimpleRateLimitFilter` 使用 JVM 内的 `ConcurrentHashMap`，没有 `RedisTemplate` 调用。因此 Redis 当前没有承载已实现业务状态，也没有跨实例限流。

<span style="color:red">可选改进：Transactional Outbox</span>

当前异步链路是先提交业务数据、再发送 RabbitMQ。生产化可在同一数据库事务写入 `outbox_events`，由独立发布器可靠投递并标记成功，同时保留消费者幂等检查。
