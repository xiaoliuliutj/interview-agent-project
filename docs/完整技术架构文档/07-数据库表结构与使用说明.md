# 数据库表结构与使用说明

## 1. 数据库边界与表分类

项目使用 PostgreSQL；基础镜像为 `pgvector/pgvector:pg16`，初始化脚本位于 `infrastructure/postgres/init/001-schema.sql` 至 `005-interview-direction-upgrade.sql`。Java 上层和 Python Agent 使用同一个 PostgreSQL 实例，但采用不同表前缀/命名空间。

| 分类 | 表 | 直接使用服务 | 说明 |
|---|---|---|---|
| Java | `candidates` | Java Resume 模块 | 用户候选人主档案 |
| Java | `resumes` | Java Resume 模块 | 简历版本、正文和文件元数据 |
| Java | `resume_analyses` | Java Resume 异步分析 | 简历分析任务和评分结果 |
| Java | `job_descriptions` | Java Interview 模块 | 岗位描述版本 |
| Java | `interview_sessions` | Java Interview 模块 | 上层面试会话状态 |
| Java | `interview_turns` | Java Interview 模块 | 上层面试轮次和评分 |
| Java | `knowledge_bases` | Java KnowledgeBase 模块 | 知识库原文、文件和向量任务状态 |
| Python | `agent_interview_sessions` | Python `PostgresInterviewSessionRepository` | Agent 完整会话 JSON 和版本 |
| Python | `agent_long_term_memories` | Python `PostgresLongTermMemoryRepository` | 用户级长期记忆 JSON |
| Python | `agent_rag_chunks` | Python `PostgresRagVectorRepository` | RAG 切片、元数据和 pgvector 向量 |
| 共享关系 | 无同名共享表 | Java/Python 通过 HTTP 协议和业务 ID 关联 | `knowledge_base_id` 等 ID 跨层传递，但不是外键共享表 |

## 2. Java 层表

### 2.1 `candidates`：候选人主档案

## 4. 跨层共享关系

项目没有一张同时由 Java JPA 和 Python SQLAlchemy 共同映射的表。跨层关系如下：

1. Java `knowledge_bases.id` 作为请求字段传给 Python `agent_rag_chunks.knowledge_base_id`；Java 保存原文和业务状态，Python 保存切片与向量。
2. Java `resumes.id`、`candidates.id` 和 `user_id` 作为 Python 简历激活/评价请求的业务标识；Python 将评价写入自己的 `agent_long_term_memories.memory_data`，不更新 Java `resume_analyses`。
3. Java `interview_sessions.id` 与 Python `agent_interview_sessions.session_id` 通常使用同一会话标识，但分别保存上层展示状态和下层 Agent 全量状态。
4. Java `interview_turns` 与 Python `session_data.turns` 保存同一轮次的两个视图；Java 负责报告查询，Python 负责 Agent 状态机。
5. `run_id` 是跨层幂等协议字段：Java `interview_turns.run_id` 与 Python 会话/长期记忆 JSON 中的运行记录共同防止重复提交，但没有独立的共享表。

## 5. 初始化与迁移

`001-schema.sql` 创建基础表和 pgvector 扩展；`002-feature-upgrade.sql` 为旧卷补列并创建 Agent 表；`003-interview-report-upgrade.sql` 增加面试计数/评分；`004-web-source-metadata.sql` 增加网页来源；`005-interview-direction-upgrade.sql` 统一面试方向字段。Java 的 `spring.sql.init.schema-locations` 只执行 `web-source-metadata.sql`，完整初始化由 Docker PostgreSQL 的 `/docker-entrypoint-initdb.d` 执行。

## 6. 审核结论

当前数据库共识别 10 张表：Java 7 张、Python 3 张、无直接共享表。字段、类型、含义、实体/ORM 文件和实际使用服务均已列出；跨层仅通过 HTTP 携带业务 ID 和数据快照，不应把业务 ID 相同误认为数据库外键共享。
