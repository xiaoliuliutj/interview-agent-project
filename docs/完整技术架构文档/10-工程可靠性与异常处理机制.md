# 工程可靠性与异常处理机制

本文只记录仓库中已经实现的可靠性机制，所有文件和行号均以当前源码为准。文中“重试”表示代码确实会再次执行；没有实现的熔断、分布式限流或 Redis 锁不会被描述成现成功能。

## 1. Java Web 层异常统一处理

入口文件：`java-backend/src/main/java/com/interviewguide/common/web/ApiExceptionHandler.java:27-141`。

`@RestControllerAdvice`（第27行）让该类接管所有控制器异常。各处理函数的行为如下：

1. `handleBusiness`（31-35行）接收 `BusinessException`，直接采用异常携带的 HTTP 状态、业务 code、是否可重试、runId/sessionId/stage，并调用 `response` 组装统一 `ApiErrorResponse`。
2. `handlePythonAgent`（37-46行）接收 Java 调 Python 时抛出的 `PythonAgentException`；可重试错误映射为 503，不可重试错误映射为 502，同时记录 requestId。
3. `handleValidation`（47-55行）从 `MethodArgumentNotValidException` 的第一个字段错误提取字段名，返回 400、`VALIDATION_FAILED`，并明确不可重试。
4. `handleConstraintViolation`（57-62行）处理参数约束违规，同样返回 400。
5. `handleUnreadableBody`（64-69行）处理 JSON/请求体无法解析，返回 400、`REQUEST_BODY_INVALID`。
6. `handleMissingHeader`（71-77行）处理缺失请求头，返回 400，并把缺失的 header 名放入提示。
7. `handleUploadLimit`（79-84行）处理 `MaxUploadSizeExceededException`，返回 413、`UPLOAD_TOO_LARGE`。
8. `handleDataAccess`（86-92行）处理 Spring `DataAccessException`，记录堆栈并返回 503、`DATA_SERVICE_UNAVAILABLE`，标记可重试。
9. `handleNotFound`（94-99行）和 `handleMethodNotAllowed`（101-106行）分别把路由不存在、HTTP 方法不支持映射为 404/405。
10. `handleMediaType`（108-113行）把不支持的媒体类型映射为 415。
11. `handleUnexpected`（115-120行）兜底捕获 `Exception`，记录错误并返回 500、`INTERNAL_SERVER_ERROR`，标记可重试。
12. `response`（123-129行）创建 `ApiErrorDetail`，再用 `ResponseEntity.status(status)` 写出状态码和统一 JSON 结构。
13. `requestId`（131-136行）优先读取过滤器属性，再读请求头，二者都缺失时生成 UUID，保证错误响应始终可追踪。
14. `firstNonBlank`（138-140行）在异常自带 requestId 为空时回退到当前请求 requestId。

### 请求 ID 和日志关联

`java-backend/src/main/java/com/interviewguide/infrastructure/web/RequestIdFilter.java:16-41` 的 `RequestIdFilter` 在最高优先级运行。`doFilterInternal`（22-34行）调用 `normalize`，把合法的 `X-Request-Id` 写入 request 属性和响应头，并放入 SLF4J MDC；`finally` 中移除 MDC，避免线程复用造成串号。`normalize`（36-41行）只接受不超过 128 个字符且匹配 `[A-Za-z0-9._:-]+` 的值，否则使用随机 UUID。

## 2. Java 调 Python 的超时、有限重试和退避

### HTTP 超时

文件：`java-backend/src/main/java/com/interviewguide/pythonagent/config/PythonAgentHttpConfiguration.java:14-34`。

`agentRestClient` 读取 base URL、连接超时（默认 2 秒）和读取超时（默认 11 分钟）；第24-27行强制 HTTP/1.1 并设置连接超时，第28-29行设置读取超时，第30-33行构造带 base URL 的 `RestClient`。因此连接失败或 Python 长时间无响应不会无限等待。

### Java 重试执行器

文件：`java-backend/src/main/java/com/interviewguide/infrastructure/reliability/AgentCallExecutor.java:10-43`。

`AgentCallExecutor` 构造器（16-20行）从配置读取最大尝试次数和退避毫秒数，并把次数至少限制为 1、退避限制为非负。`execute`（22-34行）循环调用传入的 HTTP 操作；只有 `PythonAgentException.retryable()==true` 且未达到上限才重试，第30行调用 `sleepBeforeRetry`。到达上限或错误不可重试时立即抛出原异常。`sleepBeforeRetry`（36-43行）按固定退避休眠；线程被中断时恢复中断标记并抛出不可重试异常。

### HTTP 适配器的异常分类

文件：`java-backend/src/main/java/com/interviewguide/pythonagent/mapper/HttpPythonAgentClient.java:43-97`。

`initialize`、`respond`、`complete`、`evaluateResume`、`activateResumeMemory`、`indexRag`、`deleteRag`、`fetchWeb`、`crawlWeb`（43-51行）全部通过 `callExecutor.execute` 包裹，因而共享有限重试策略。`sessionProgress`（55-63行）是状态查询，网络异常不抛错而返回 `STATUS_UNAVAILABLE`，避免轮询接口拖垮前端。

`post`（65-80行）先调用 `validateRequest`（89-97行）执行 Bean Validation；字段非法构造不可重试的 `PythonAgentException`。正常响应为空（68-70行）视为可重试错误；HTTP 错误先由 `parseStructuredError`（82-87行）尝试读取 Python 的结构化错误，解析不到时 5xx 标记可重试、4xx 标记不可重试；网络异常（77-79行）标记可重试。

## 3. RabbitMQ 任务可靠性

拓扑定义在 `java-backend/src/main/java/com/interviewguide/infrastructure/messaging/RabbitTaskConfiguration.java:16-61`：主交换机 `interview.agent.work`、主队列 `interview.agent.work.execute` 和 routing key `agent.work.execute`（19-21行）；队列声明持久化并设置死信交换机/路由键（29-33行）；死信交换机和队列在 41-50 行绑定；54-60 行启用 Jackson JSON 转换和 `RabbitTemplate`。发布方和消费方均是 Java，Python 是被 Worker 通过 HTTP 调用的下游，不直接连接 RabbitMQ。

### 简历分析任务

`ResumeAnalysisWorker.enqueue`（`resume/service/ResumeAnalysisWorker.java:48-52`）把 `RESUME_ANALYSIS`、analysisId、userId 封装成 `AgentWorkTaskMessage` 发布。`process`（54-125行）先查询分析记录和简历；记录不存在、已取消、简历不是候选人的当前版本时直接返回或取消，因为这些是过期消息，不应重试。第69-71行通过 `beginAttempt` 记录尝试次数；第74-84行先调用 Python `activateResumeMemory`，第89-107行调用 `evaluateResume`。Python 返回非 2xx 时，可重试错误抛出 `PythonAgentException`，不可重试错误持久化为失败。第113-124行捕获运行时异常：取消任务直接结束；可重试且尝试次数未达 `maxDeliveryAttempts` 时记录可重试失败并重新抛出，让 Spring listener 重投；否则把分析标记失败。

### 知识库索引任务

`KnowledgeBaseIndexWorker.index`（`knowledgebase/service/KnowledgeBaseIndexWorker.java:38-42`）发布 `KNOWLEDGE_BASE_INDEX` 消息。`process`（44-100行）校验知识库存在性、所有者和删除标记，第56-57行用 `markIndexing` 防止重复处理；第60-73行调用 Python `/v1/agent/rag/index`，根据响应决定成功、失败或抛出可重试异常；若处理期间知识库被删除，第76-83行调用 Python `/v1/agent/rag/delete` 做向量清理。第86-99行把异常状态写回数据库，业务/校验错误被确认（ack），只有临时 Python 依赖错误继续抛出交给 listener 重试。

### 消费入口和坏消息

`RabbitAgentWorkConsumer.consume`（`infrastructure/messaging/RabbitAgentWorkConsumer.java:22-39`）监听主队列。消息为空、任务类型、资源 ID 或用户 ID 缺失时记录并丢弃；按任务类型分派给两个 Worker；未知类型记录错误；资源 ID 无法转数字时捕获 `NumberFormatException` 并丢弃。Spring AMQP 的 listener retry 使用 `spring.rabbitmq.listener.simple.retry.max-attempts`；当前 `application.yml:24-32` 通过环境变量默认 2 次，初始间隔 1000ms、倍增 2、最大间隔 10000ms（Worker 构造器在配置缺失时的代码回退值是 3）。`default-requeue-rejected: false` 使最终未确认的异常进入队列声明的 DLX/DLQ。过期、删除或非法业务消息在 Worker 内被 ack，不进入死信，避免无意义重放。

## 4. Python FastAPI 异常、超时和模型重试

文件：`python-agent/app/api/application.py:289-307`。`RequestValidationError` 返回 HTTP 400；`ApplicationException` 通过 `_error_json_response` 返回业务错误（HTTP 200，错误体中的 code/type/retryable 表示业务结果）；未知 `Exception` 记录堆栈并返回 HTTP 500。`_mark_failed_interview_progress`（320-328行）仅对 `/v1/agent/respond` 将进度写成 FAILED，避免 UI 一直显示 evaluating。

`respond`（93-130行）使用 `asyncio.wait_for(..., timeout=150)` 包住一轮回答；超时标记进度失败并抛出不可重试的 `AgentDependencyError`。`InterviewAgentService._run_interview_node`（`agents/interview/service.py:112-125`）对规划、评估、路由和提问等单个模型节点设置 45 秒超时；超时转换为可重试 `AgentDependencyError` 并标记 FAILED。

统一异常分类在 `python-agent/app/common/exceptions.py:8-146`：`RequestError`、`ConsistencyError`、`ModelOutputError`、配置错误和 `RagConfigurationError` 默认不可重试；`RateLimitError`、`AgentDependencyError`、`RagDependencyError` 可重试；内置 `TimeoutError` 映射为 501/MODEL_TIMEOUT，`ConnectionError` 映射为 503/DEPENDENCY_NETWORK_ERROR，`ValueError`/`TypeError` 映射为请求错误。`ExceptionHandler.to_error_info` 和 `to_code`（116-146行）负责将异常转换为稳定的错误结构。

模型/Embedding 重试由 `python-agent/app/infrastructure/reliability/retry.py:15-48` 实现。`execute` 最多执行 `RetryPolicy.max_attempts` 次，每次用 `asyncio.wait_for` 限制为 `attempt_timeout_seconds`；仅当异常类型名在 `retryable_errors` 集合中才重试，退避为指数增长并受最大毫秒数限制。最终仍失败时包装为可重试 `AgentDependencyError`。Embedding 适配器在 `python-agent/app/rag/embedding.py:18-50` 将 SDK `max_retries` 设为 0，统一交给 `AsyncRetryExecutor` 的 `embed_documents`/`embed_query` 执行，避免 SDK 内外双重重试。策略由 `policy.py:20-45` 从 `resources/agent/reliability.json` 读取并校验次数、退避、单次超时和结构化输出修复次数，配置错误抛出不可重试的 `ReliabilityConfigurationError`。

## 6. 并发、幂等与进度状态

Java 面试持久化服务 `InterviewSessionPersistenceService.applyAnswer`（`interview/service/InterviewSessionPersistenceService.java:57-118`）先按 `runId` 查询已保存回答；同一 runId 携带不同 session 或答案抛出 `RUN_ID_PAYLOAD_MISMATCH`，相同 payload 直接返回，形成幂等重放。随后比较 `stateVersion`，不一致抛出 `SESSION_CONCURRENT_MODIFICATION`，防止并发覆盖。

Python `InterviewAgentService` 的 `initialize_session`（`agents/interview/service.py:127-189`）和记忆服务使用 runId+fingerprint 检测重复提交；冲突抛出 `ConsistencyError`。`MemoryService` 的 repository 协议（`memory/repository.py:8-15`）要求 `save(..., expected_version)`，调用方以期望版本执行乐观并发控制。回答/总结完成后，Python 服务用 `_report_progress` 更新阶段；异常路径统一调用 `mark_progress_failed`，状态查询接口返回 FAILED 而不是假装 IDLE。

## 7. 文件、URL、大小和限流安全

Java 文件路径保护在 `resume/service/ResumeFileStorageService.java:17-53`：根目录先 `toAbsolutePath().normalize()`；原始文件名取 `Path.getFileName()` 去掉目录；目标路径 normalize 后必须 `startsWith(root)`，否则拒绝路径穿越。读写删操作全部重复该校验。上传过大由 Spring 异常处理器返回 413，具体上限由 `spring.servlet.multipart.*` 配置决定。

Python URL SSRF 防护在 `tools/web_reader.py:190-215`：仅允许 http/https、禁止用户名密码和非 80/443 端口；DNS 解析出的地址若为私有、回环、链路本地、组播、保留或未指定地址则拒绝。每次重定向重新校验 URL（218-235行），响应只接受 HTML，单页字节数和 Markdown 长度受上限约束（237-251行）。抓取器还限制总时长、总字节数、尝试次数、同域名和最大页面数（325-437行）。

Java `SimpleRateLimitFilter`（`infrastructure/ratelimit/SimpleRateLimitFilter.java:25-61`）按客户端 IP+URI 做进程内固定一分钟窗口，默认每分钟 60 次；超限返回 429 和 `Retry-After: 60`。健康检查和 actuator 被排除。该限流不是 Redis 分布式限流，多实例部署时每个实例各自计数。

## 9. 持久化冲突、配置错误与生命周期保护

Python PostgreSQL repository 的 `IntegrityError` 处理位于 `infrastructure/persistence/interview_session_repository.py:36-44` 和 `long_term_memory_repository.py:40-47`：创建同一 session/user 的并发插入时回滚并转换为 `ConsistencyError`。两个 repository 的 `save` 使用 `WHERE ... state_version == expected_version`（会话 55-86 行、长期记忆 49-76 行）；更新行数不是 1 时回滚并抛并发冲突，而不是静默覆盖别的请求。

`MemoryService.record_turn`（`memory/service.py:122-144`）和 `finalize_session`（146-175行）遇到 `ConsistencyError` 会回读最新记录；如果幂等的 turnId/sessionId 已经存在则返回最新值，否则继续抛出，防止重复提交与真正并发冲突混淆。`record_resume_analysis`（177-234行）通过 runId+fingerprint 拒绝同一运行 ID 的不同输入。

配置加载器对文件不存在、JSON 解析失败、字段缺失和非法范围统一转换为稳定配置异常：`RetryPolicy.load`（`infrastructure/reliability/policy.py:20-45`）、`RagPolicy.load`（`rag/policy.py:25-64`）、Memory/Workflow/Skill 配置加载器的对应 `except` 均在启动或首次装配时失败，不使用半解析配置运行。提示词加载器 `common/prompt_loader.py:20-44` 对缺失文件和越界路径抛配置错误，避免静默读取错误模板或目录外文件。

| RAG/网页降级 | `rag/service.py:103-126`、`tools/web_search.py:67-100` | 过滤器不支持、公共网络故障 | 本地过滤或空证据继续面试 |
| 乐观锁与幂等 | `InterviewSessionPersistenceService.java:63-82`、`memory/service.py:138-175` | 重复请求、并发覆盖 | 重放返回已有结果，真正冲突抛 ConsistencyError |
| 文件/SSRF/限流保护 | `ResumeFileStorageService.java:21-53`、`tools/web_reader.py:190-215`、`SimpleRateLimitFilter.java:37-60` | 路径穿越、内网访问、请求洪峰 | 拒绝危险输入，返回 413/429 或安全错误 |

## 11. Redis 相关结论

Redis 目前只在依赖、配置或 Docker 基础设施中出现，业务代码没有 `RedisTemplate`、Redisson、Jedis、Lettuce 或 Python Redis 客户端调用。上述请求 ID、限流计数、RAG 缓存、会话进度和幂等记录均为 JVM/Python 进程内内存结构；进程重启或多实例不会共享。若后续需要跨实例一致的限流、缓存或幂等，应单独设计 Redis key、TTL、序列化和故障降级，不能把当前内存实现误读为 Redis 机制。
