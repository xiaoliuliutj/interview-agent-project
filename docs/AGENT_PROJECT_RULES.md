# AI Agent 面试项目改造：全局规则

本文档只记录后续工作必须遵守的整体要求，不记录具体代码、接口、框架版本、配置项或实现步骤。需要记录业务模块、技术选型和重构顺序时，分别使用 PROJECT_MODULE_DESIGN.md 和 REFACTOR_ROADMAP.md。

## 一、项目目标

将现有 InterviewGuide 改造成一个面向实习面试展示的 Python Agent 项目。

项目必须具备完整、可运行、可演示的全链路，并在一个核心 Agent 能力上形成适度深入。项目以“能够理解、能够实现、能够向面试官讲清楚”为最高优先级，不追求生产级复杂度或技术数量。

## 二、参考来源

- Agent 学习来源：[datawhalechina/hello-agents](https://github.com/datawhalechina/hello-agents)
- 原始业务项目：[Snailclimb/interview-guide](https://github.com/Snailclimb/interview-guide)
- 面试知识参考：[代码随想录：大模型/LLM 面经问题](https://programmercarl.com/qita/0022.llminterview.html)

后续设计应结合以上三类资料：

- 从 Agent 学习来源中提炼概念和方法。
- 从原始业务项目中复用业务场景和已有资产。
- 从面经问题中校准项目需要覆盖的知识点和面试表达。

## 三、整体要求

### 1. 整个项目的技术栈与技术选型

- 技术栈必须服务于项目目标和面试表达，避免为了展示技术而引入不必要的组件。
- 选型应支持完整的前端、后端、Agent、模型调用、知识检索和数据持久化链路。
- 前端界面和交互能力可以直接复用；Java 业务后端与 Python Agent 服务必须从零构建。
- 原始项目的后端代码仅作为业务流程、接口形态和工程设计的参考，不直接作为本次后端实现的基础。
- 每个重要选型都必须能够说明选择原因、适用范围、主要权衡和可能的替代方案。
- 技术栈应控制在个人能够掌握和解释的范围内，不追求“大而全”。

### 2. 整个项目的架构

- 项目必须体现清晰的分层和职责边界。
- 前端负责用户交互和结果呈现；从零构建的 Java 业务后端负责业务流程、数据和系统边界；从零构建的 Python Agent 服务负责智能决策、工具协作和模型相关能力。
- Java 后端是用户、资料、面试会话、业务任务和业务结果的唯一管理方；Python Agent 是记忆、RAG 数据、Agent 运行状态和工具执行记录的唯一管理方。
- Java 与 Python 分别管理各自的数据边界，不共享写入同一业务数据表；跨服务协作通过稳定接口和幂等标识完成。
- 各层之间必须通过清晰、稳定、可解释的契约协作。
- 架构应支持流式交互、会话状态、知识检索和结果追踪等核心体验。
- 架构设计以单体或轻量服务拆分为主，不追求复杂的分布式治理。
- 整个系统必须具备在虚拟机中部署和运行的能力，部署后的核心功能应可被访问和演示。
- 必须能够从用户操作开始，讲清楚请求如何经过各层并最终返回结果。

### 3. 主要模块的知识点

主要模块至少应覆盖以下知识方向：

- Agent 基础：Agent 与普通问答、固定工作流的区别，以及任务决策和执行过程。
- 工具协作：工具定义、工具选择、工具结果处理、失败恢复和执行终止。
- 大模型应用：提示词设计、结构化结果、多轮上下文和流式响应。
- 知识库与 RAG：文档处理、知识组织、检索增强、来源引用和结果可信度。
- 面试业务：简历理解、岗位要求理解、问题生成、追问、回答评价和反馈报告。
- 全链路工程：前后端通信、状态管理、数据持久化、日志记录、异常处理和基础测试。
- 面试表达：每个主要模块都要能说明其作用、输入输出、关键难点、设计权衡和可改进方向。

知识点应通过项目功能体现，不以单独堆砌术语为目标。

### 4. 内容范围边界

- 项目面向实习面试，不以生产上线为目标。
- 必须完成一个完整的文本 Agent 主流程，并保证前后端能够联动演示。
- 必须保留完整的部署闭环，使项目能够在虚拟机环境中完成启动、访问和基础验证。
- 必须有一个可深入讲解的核心方向，其他方向做到完整、清晰、适度即可。
- 可以参考原项目的业务能力和交互流程，但不直接复用其后端实现，且不能让功能数量掩盖 Agent 主线。
- 暂不要求复杂的多 Agent 协作、重型基础设施、完善的企业级权限体系、高可用治理或复杂语音系统。
- 不进行与目标无关的大规模重构，不为了追求“高级”而牺牲可运行性和可解释性。
- 所有新增内容都应回答一个问题：它是否提升了项目完整性、Agent 能力或面试展示价值。

## 四、协作约束

- 后续分析、设计和实现必须以本文档为最高项目约束。
- 任何具体技术方案应先说明其对应的整体要求，再决定是否采用。
- 每个阶段完成后，都要补充可运行验证和面试讲解要点。
- 发现新资料、新决策或范围变化时，先更新本文档或相应的专题设计文档。
- 未经明确要求，不扩大项目目标，不擅自引入与面试目标无关的功能。

### 首次功能实现说明规范

后续首次实现某个功能时，必须按照以下结构向用户说明；同一功能后续的完善、修复和优化不再强制重复该结构：

1. 功能需求
2. 功能的主流解决方案
3. 本项目的选型及原因
4. 具体实现方式
5. 相关知识点

“相关知识点”只列出需要进一步学习的主题，不在该部分展开详细教学。只有真正开始实现功能时才使用该结构，普通讨论、方案调整和后续完善不受此格式限制。
