# InterviewGuide 部署文档

## 1. 部署拓扑

浏览器 → `frontend:80` → `java-backend:8080` → `python-agent:8000`。Java 同时访问 PostgreSQL、Redis 和 RabbitMQ；Python 访问 PostgreSQL、模型服务和 Embedding 服务。

Python 在 `infrastructure/docker-compose.yml` 中仅配置 `expose: 8000`，没有宿主机 `ports`。`frontend/nginx.conf` 与 `frontend/vite.config.ts` 只代理 Java，前端绝不能直接调用 Python。

## 2. 环境变量

在 `infrastructure/.env` 配置：

```dotenv
POSTGRES_PASSWORD=change-me
RABBITMQ_PASSWORD=change-me
MODEL_NAME=your-model
MODEL_API_KEY=your-key
AGENT_SYSTEM_KNOWLEDGE_BASE_IDS=system-kb-id
```

可选配置包括 `MODEL_PROVIDER`、`MODEL_BASE_URL`、`MODEL_TEMPERATURE`、`EMBEDDING_MODEL`、`EMBEDDING_API_KEY`、`EMBEDDING_BASE_URL` 和 `PYTHON_AGENT_READ_TIMEOUT`。

<span style="color:blue">新知识：环境变量</span>

环境变量将密码、模型密钥和服务地址从源码剥离；不同环境可以使用不同 `.env`，且不能提交真实密钥。

## 3. 启动

1. 安装 Docker Desktop 或 Docker Engine。
2. 将 Java PDF 所需字体放入 `infrastructure/fonts/`。
3. 在仓库根目录执行：

```powershell
docker compose --env-file infrastructure/.env -f infrastructure/docker-compose.yml up --build -d
```

4. 检查服务状态：

```powershell
docker compose --env-file infrastructure/.env -f infrastructure/docker-compose.yml ps
```

浏览器只访问前端映射的 80 端口；不得暴露 Python 8000 给浏览器或公网。

Python 镜像通过 `python-agent/Dockerfile` 复制 `app/` 和 `resources/`。`resources/` 是运行时 Prompt、Skill、RAG 策略与六阶段工作流的唯一来源；不要在镜像内保留旧 `config/` 副本，否则会产生两套配置来源。

## 4. 数据库升级与排障

新卷首次运行 `001-schema.sql`；已有数据使用 `002-feature-upgrade.sql` 与 `005-interview-direction-upgrade.sql` 兼容升级。脚本只增加结构或迁移旧字段，不删除历史数据。

前端 502 时检查 Nginx 与 Java 健康检查；Java 调 Python 失败时检查 Python `/health`、Docker DNS、模型配置和超时；模型 JSON 错误时检查 `StructuredOutputInvoker` 与 `resources/prompts`；队列积压时检查 RabbitMQ 与 Java 消费者；向量检索失败时检查 `knowledge_bases.vector_status`、`vector_error` 与 `agent_rag_chunks`。答题重试必须复用同一 `runId`。

## 5. 验证清单

- Python：依赖完整时运行 `python -m compileall -q app tests` 与 `pytest`。
- Java：在 Maven 可用环境运行 `mvn test`；本仓库没有 Maven Wrapper。
- 前端：运行 `pnpm install --frozen-lockfile` 后执行 `pnpm build`。
- 网络边界：前端不得出现 `python-agent:8000`、`localhost:8000` 或 Python `/v1/` 代理；Compose 中 Python 必须仅使用 `expose`。

<span style="color:red">生产建议：内部认证</span>

Docker 私有网络避免浏览器直连 Python，但生产环境仍建议 Java→Python 使用短期服务令牌或 mTLS：在 `HttpPythonAgentClient` 写入内部认证头，在 Python `application.py` 的依赖层验证；健康检查可使用独立只读路径。
